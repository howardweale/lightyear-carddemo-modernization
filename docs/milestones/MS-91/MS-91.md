### Why this milestone matters

MS89 demonstrated a bounded repair workflow but required disclosed controller revisions. MS90 applied a separately authorized comparison policy to retained evidence while preserving the original failed verdict. MS91 moved the acceptance decision before generation: the factory knew its permitted task, and the judge already knew the rules by which the result would be accepted.

The factory generated the Java candidate. The engine executed and judged the same candidate on both databases. A person had already approved the comparison scope and resource budget. Nobody changed expected business values, the judge, the controller or the budget during this run.

### The observed journey

The generated application journey created a customer and stocked product, used fractional prices, tax, a discount, Unicode text, an empty optional field and a fractional shipment timestamp, and completed two partial shipments followed by one aggregate invoice and payment. It then created and reversed a credit note, exercised two overlapping explicit-row-lock updates, and injected a pre-commit failure followed by rollback and caller-keyed retry.

These are several operations within one bounded journey, not a claim that every credit, reversal, concurrency or recovery scenario has been covered.

## The declared comparison policy

### Numeric eligibility follows native column types

The version-3 judge uses the verified datatype inventory, which identifies 9,393 Oracle NUMBER to PostgreSQL numeric columns. Native catalogs must match the frozen declarations. Numeric trace values must also bind to independently captured cells; the stock aggregate binds to captured numeric stock rows. A field name or numeric-looking text is insufficient.

Equality uses exact decimal values without rounding or tolerance. Exponent notation, nonfinite values, floating-point inputs and unsupported wrappers are rejected, including when both sides contain the same invalid spelling. SQL nulls remain nulls. An unbound intermediate trace is compared as an exact string rather than receiving a numeric exception.

The initial work order specifies consistent plain-decimal trace serialization. That requirement was fixed before generation. Earlier retained observations still show their original formatting differences; they were not rewritten to satisfy this campaign.

### One register for rules and retained differences

The frozen register contains 15 column rules, one engine-identity metadata rule and 6,024 historical difference witnesses. Every rule has an owner, effective date, review date and measured scope. Numeric eligibility spans the complete typed inventory, while UUIDs, audit clocks, workflow text and engine metadata retain their separate, bounded predicates.

| Rule or observation | Required treatment |
|---|---|
| Numeric cell values | Exact decimal equality with captured provenance |
| Numeric audit clocks | Differences need their separate owned clock rule |
| UUIDs and audit metadata | Re-execute the registered validation predicate |
| Unknown or unmeasured rule scope | Refuse admission rather than substitute zero |
| Unbound intermediate trace values | Exact string comparison |

### The accepted timestamp decision

The existing signed decision covers only `adempiere.m_inout.shipdate`: Oracle DATE compared with PostgreSQL timestamp without time zone in verified UTC capture sessions. Oracle must have no fraction, and every date and time component through seconds must match. The rule does not round into a different second. Raw fractions and their loss remain visible.

**Owner:** Howard Weale. **Effective:** 26 September 2026. **Review:** 25 December 2026. Another column, another datatype, an unsupported timezone context, or a business requirement for subsecond ordering or timing remains outside the decision.

### What the judge observed

The new run validated 2,746,888 numeric cell observations and retained 6,038 admitted raw row differences plus 15 admitted trace differences. No row or trace differences remained unresolved. These are observation and witness counts, not millions of independent test cases; much of the observed database content is inherited seed data.

## Frozen execution and measured effort

### Declare once and execute once

The plan pins the implementation and public-input hashes, comparison register, database images, application revision, CLI binary identity, requested model and reasoning setting. It authorizes at most 11 total client calls and four hours of local execution. Each client call has a 15-minute limit. The candidate is limited to one Java file, 60,000 bytes and 650 changed lines.

There is no resume or amendment command for this campaign. A changed judge, controller, input or exhausted budget stops it. Further work requires a new declaration and authorization. Every attempt binds its judge hashes and rule version to the generated candidate and native result.

The analyst channel permits only compiler diagnostics, supported API type mismatches and a verified out-of-footprint table and call. It can select closed diagnostic records, not send free-form repair instructions or expected business outputs. In this run, no analyst call was needed.

The final audit matches candidate bytes to the model proposal and verifies the input and result chain. The zero applies to candidate source and repair messages after the initial specification. It does not mean no person prepared the work order, controller, judge or policy. Since the first candidate passed, the result does not demonstrate the success rate of analyst-led repairs.
