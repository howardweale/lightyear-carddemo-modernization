# Runtime closure producer: next separately authorized step

Prepared code; not launched or frozen. Inventory-only authority does not cover this operation.

The proposed single network-free pinned-image container compiles the two public runtime agents and the plain JUnit catalogue test, starts the actual offline Tycho/Equinox test runtime without any database container or native pair, and observes resolved bundle IDs/states, defining framework JAR, JVM home, Java classpath and effective configuration. It retains the loaded sources of the six application/framework target classes. The worker requires one unambiguous effective Surefire properties file, including all declared booter classpaths; unknown keys, unresolved bundles and missing output fail closed.

Inventory is derived from those observed paths, not a recursive Maven-cache scan. Bundle-Class-Path controls nested/folder bundle extraction. The worker uses the pinned runtime's jimage against a byte-bound copy of lib/modules and records measured class counts and expanded bytes. The host verifies the exact public source bytes, snapshot, fresh distinct Tower decision, image, time window and JVM hash. It signs the closure receipt only after the owned-container cleanup check succeeds. Independent closure assembly re-verifies the launch receipt and reconstructs the observed binding.

Proposed limit: one container, 2,700 runtime seconds plus 600 cleanup seconds; a 60-minute window permits up to five minutes for starting. Zero retries, models, native pairs, database containers and external network. No prune/global removal. All failure output is preserved.

Required before any Docker: publish the tested source commit, choose a fresh window, assemble an immutable snapshot including the host's full import closure, bind the known JVM hash, prepare the exact Tower request, and obtain Howard's decision. No window or decision is fabricated here. The fresh runtime may expose further configuration gaps; such a failure stops, without an automatic retry.

The subsequent scoped extraction and five-path census remain separate prospective steps. The Oct 9 generated-class proof deadline and documented JVMTI alternative remain in force.
