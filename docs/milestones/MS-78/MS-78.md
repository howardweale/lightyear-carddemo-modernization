# MS78 — Reliable local agent runs and cancellation

Status: **implemented and tested for the retained CloudBank workflow**.

Delivered in [PR #208](https://github.com/howardweale/lightyear-carddemo-modernization/pull/208).

## Why it matters

An operator or assistant can start a verification run, disconnect, reconnect and
ask it to stop without losing the run's identity or confusing a cancellation
request with a completed cancellation. The same project-bound service is exposed
through the JSON command line and a local MCP server.

## What was delivered

PR #208 adds durable, project-scoped cancellation to the existing local agent
workflow. A cancellation request is recorded independently of the client
connection. The worker acknowledges it in the verified journal, terminates its
owned subprocesses and stops further actions. Resume respects the cancellation
request, while completed results remain immutable. The current-plan MCP resource
explicitly checks that the project's configuration has not changed.

The workflow supports capability discovery, plan review, idempotent start,
status, paginated events, verification, export, resume and cancellation. Run IDs
and reviewed plan hashes connect these operations. Human approvals remain
separate, signed decisions in Control Tower.

## Follow-up client usability

The A2 cleanup makes event pages default to 25 consistently in the service, CLI,
MCP tool and first-page resource. Smaller explicit pages remain supported.
Unconfirmed dispatch responses expose `retriable: true`; recovery inspects and
resumes the same durable run rather than creating another run. A missing or
incompatible optional MCP SDK produces a structured installation hint on stderr
and exit code 2, with no traceback or protocol output on stdout.

## Evidence and verification

The merged cancellation work covers queued and active cancellation, owned-process
termination, reconnect, publication races, crash recovery and immutable terminal
evidence. The follow-up tests cover default page contents, cursor continuation,
retry metadata and missing-SDK startup behavior.

```bash
PYTHONPATH=src python -m unittest tests.test_agent_workflow tests.test_agent_mcp -v
```

The real MCP integration tests require the optional `.[agent]` dependencies.
See the [local agent runbook](../../local-agent-workflow.md) for installation,
Windows worker ownership, operation contracts and exit codes.

## Boundaries

This workflow verifies retained evidence. It does not execute fresh Oracle or
AlloyDB workloads, modernize arbitrary customer applications, grant human
approval or establish production readiness. A verified journal can still end at
a human-decision gate. A cancellation request is not terminal until acknowledged.

This record complements the [engine-to-history work](../MS-74/MS-74.md): durable
control and cancellation preserve the meaning of the terminal history record.
