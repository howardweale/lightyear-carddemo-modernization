## Review boundary and counting method

This documentation-only review covers October 1 through **October 10, 2026**,
pinned to the published records below. It does not re-audit private archives,
verify signatures anew, inspect live Docker or assert a launcher's current state.
Historical verification results are attributed to the cited reviews. No code,
calibration evidence, machine configuration, service or running checkout was
changed to produce this report. Operator review, not independent attestation.

The ledger counts **failure families**, not every aborted command or retry.
Windows denial setup, for example, has several preserved attempts in one family.
Review findings include missing capabilities identified before launch. A commit
can mitigate several findings; one finding can require several commits. “Fix”
identifies the correction or mitigation and its limits, not a claim that the
native business journey passed. Unfixed rows can cite preservation or diagnostic
commits without counting them as fixes.

The denominator is the distinct SHA union reachable from these three heads,
excluding merges, selected by Git `--since=2026-10-01T00:00:00-07:00` and either
case-insensitive `B06` in the subject or a changed path matching `b06`,
`stage-b-06` or `PostingObserver`. No selected commit precedes October 3.
Adjacent generic dependency changes without that footprint are outside the count.
Separate cherry-pick SHAs count separately: this is not a unique-patch or labor
estimate. Appendix A lists every selected commit and allocation. Mixed commits
receive one class for their principal delivered change; plan/publication-only
commits are B06-specific.

**Reusable** means another target benefits as shipped. **Adaptable** means the
mechanism transfers but remains coupled to B06, iDempiere, Tycho/Equinox or the
campaign's evidence schemas. **B06-specific** means this campaign's business
contracts, windows, approvals or fixtures. The narrower class is used where
uncertain: generic-looking observer/artifact code is adaptable, not a ready
platform package. A regression test alone does not make it packaged.

### What is kept, cleaned up, superseded or unrecoverable?

| Material | Disposition supported by records | Platform value and limit |
| --- | --- | --- |
| Failed reports, partial audits, available event streams, receipts and source/plan/snapshot bindings | Preserved under the original failed outcome | Investigation and negative regression fixtures. An authenticated prefix does not authenticate an absent suffix. |
| Frozen inputs and superseded/expired plans | Preserved; never repurposed as a newly authorized run | Identifies the exact reviewed bytes/window. Repeated copying and publication are largely campaign overhead. |
| Private JARs, bytecode, catalogs, reference data and captured values | Kept local where captured; public metadata/hashes only | Enables replay without publishing private content. This report does not audit retention duration, backups, deletion policy or disk cost. |
| Owned containers, networks and volumes | Removed by the controller; terminal reviews record actual absence | Disposable execution resources, not the learning asset. Only exact owned resources may be cleaned up. No cleanup was performed for this report. |
| Build-once derived image | Intentionally retained locally: `sha256:554a5203449ab2d4b19089b16df5fac4e9fde3334f6762de3760f2a9d48b6268` | Avoids per-consumer rebuilding and anchors the same runtime bytes. Retention is not permission for another run. |
| Forty historical full application bundle contents | Never captured sufficiently for the later fidelity requirement | A new successful build cannot recover them. The explicitly prospective requirement amendment leaves this historical gap intact. |
| Raw JDI events triggering the two historical tracker refusals | Never serialized before the guard threw | Permanently absent from those streams. Balanced accepted events cannot identify the missing request or arm state. |
| Stress tails after timeout, disconnect or byte bound | Not credited as a complete capture | Target stdout reaching 3,200 iterations does not supply observer evidence for the missing tail. |
| Expired/rejected decisions and elapsed preparation time | Decisions remain historical; authority is spent or inapplicable | No authorization, trial pass or qualification credit transfers to a replacement plan. Elapsed time is a sunk cost. |
| Broad extraction, prefix trust, silent normalization and proposed bound increases | Withdrawn, rejected or inactive approaches remain documented | Lessons constrain future designs; these are not active admission exceptions. |
| Fixed code, host reproductions, negative tests and review rules | Retained in version control | This is platform growth. There is no demonstrated automatic model training, learning or self-improving memory from failed runs. |

The platform keeps **knowledge encoded in evidence, code and tests**. It does not
convert a failed business run into success. Runtime cleanup is mostly intentional
disposal; the serious evidence losses were data never captured in the first place.
Pre-guard diagnostics address that prospectively.
