# MS 106 Signed Factory history and local authority

Recorded October 14 2026. Implementation: [PR #339](https://github.com/howardweale/lightyear-carddemo-modernization/pull/339). Local activation was explicitly authorized by Howard.

The local Factory Tower now has a signing authority, an operator identity and a signed import of seven historical public records. The configured Tower and Factory consumer require signed evidence. This gives the operator a verifiable history while preserving every original decision's date, scope and conditions.

## Complete historical import

The importer inventories the recognized decision families at one exact source commit. It includes the original Howard decisions, scoped equivalence acceptances, duplicate-category approval, Phase 1 rerun authorization, B06 preparation and merge-hold lift. It rejects omissions, changed records, altered dates and mixed source revisions.

Dates come from the records themselves. The B06 preparation timestamp remains a preparation date; it is not represented as a new approval or a signed runtime receipt. Signing the inventory does not turn a conditional approval into an effective decision.

## Local activation

The Tower is installed as a user login service at `http://127.0.0.1:8769/`. Howard's identity has the operator, qualification-approver, campaign-authorizer and business-owner roles for the configured Factory workloads. The authority and private credentials are stored separately from the imported public evidence and are excluded from this publication.

The installation pins runtime source `5e36903a162c032179be2c97e6cc0cd88e6dcfb3` and verifies its file manifest before startup. The public evidence snapshot retains commit `b580b4f765fdd41eb505fc59bbc998136ba23024` and the original experiment provenance. A newer display or installation commit does not create new experiment results.

The signed backfill covers seven records. The local activation record confirms signed-only mode. The configured consumer launcher refreshes and verifies trust against the current journal head before use. This configuration applies to this installation; other checkouts and CI need their own explicit trust configuration.

## Validation and remaining boundaries

The focused backfill tests passed on Linux, macOS and Windows. They cover complete import, signing, activation, tampered proof rejection, changed dates, missing records and preserved conditions. All 29 PR #339 checks completed successfully on the pinned implementation head.

The local activation verification recorded Howard's four roles and the available program and status views. Operational records and private authority material remain local.
