# MS74 — Engine-to-history recording

Status: implemented. Terminal CloudBank evidence-engine runs now populate the
MS73 history index and the Control Tower's Convergence view automatically.

## Delivered behavior

After a terminal halt, the engine replays the complete journal against its exact
current inputs, policy, receipts and implementation. Only a successfully admitted
terminal journal is archived. Completed, divergent, blocked, budget-limited and
other replay-valid terminal runs retain their actual halt reason. Paused runs and
interrupted attempts remain resumable and are not counted as finished runs.

The run identity is derived from the sealed start event, not the directory name
or retained CloudBank source receipt. A compressed archive contains the full
events and run/estate/workload metadata. The permanent SQLite row binds its path,
byte count and SHA-256, and retains action counts, rounds and block counts.

Archives default to `work/workflow/history/journals`. Operators can select another
directory inside repository `work/` with `--history-dir`. The index remains at
`control-tower/run-index.sqlite3`, matching the existing read-only API. It is
ignored by Git. No customer measurements or fabricated trend is committed.

```bash
PYTHONPATH=src python3 -m lightyear_workflow.execution run \
  --run-dir work/workflow/ms74-run \
  --history-dir work/workflow/history/journals
```

Use a new run directory for a new execution. Reusing a terminal run repairs a
pending archive/index publication without executing its actions again. Reusing a
paused run resumes it. Keep the same archive directory when retrying a run.

## Failure and retention behavior

Archive publication writes and flushes a complete temporary file, then publishes
it without replacing an existing file. A failure between archive publication and
the SQLite insert leaves a recoverable archive; the next engine invocation retries
recording. Archive/index errors are surfaced to the caller and cannot be reported
as successful history persistence. The original terminal journal remains intact.

Changed archives, changed identities, symbolic output paths, invented completion
and stale execution inputs are rejected. Repeating an already indexed run is
idempotent. Repeating a run after its archive was pruned preserves the pruning
record and does not resurrect the archive. Retention remains explicitly invoked
by the operator; this milestone adds no pruning scheduler. SQLite engine journals
are separate from the compressed history archives and are not pruned by this policy.

Browser reads never create, repair or prune an index. The Convergence endpoint
reads only the existing index and reports action events, not distinct resolved
findings, current cloud health, or semantic improvement. Historical journal replay
still requires the matching implementation and inputs; index rows remain readable
after those inputs change.

## Validation

The regression suite exercises pause/resume, real engine admission, two distinct
runs, terminal block counts, archive/index failure recovery, altered archives,
source drift, resealed invented completion, retention-preserving retries, custom
archive location and read-only history projection. Existing engine regressions
also cover divergence, worker failures, bounded retries and halt reasons.
