# MS94 Qualify the equipment, then measure the factory

**Status: Stage A accepted and published; Stage B 02 running under a separate frozen declaration.**
**Date: 29 September 2026 (Stage B binding audit and fingerprint publication).**

MS94 first checks whether the judge and execution environment can reliably
accept correct journeys and reject declared faults. Only then can a later
campaign measure generated code. These human-reviewed references are test
equipment; none of their passes count as autonomous factory successes.

## What changed in the equipment

The public contracts state document shapes, required links, trace fields and
transaction boundaries. Operations uses one aggregate order-linked invoice line;
two shipment-linked invoice lines are not silently accepted. Monetary answers
remain private. Purchasing side effects are bounded by source-derived ownership,
organization, accounting history and posting rules, rather than a table whitelist.

The versioned SDK supplies typed accessors, strict trace serialization, cleanup
and explicit posting guards. Its guard does not prevent application-internal
costing or reposting; that is an explicit reviewed limit. Unknown judge exceptions
remain inspectable `judge-error` results. Business failures, execution failures,
insufficient evidence and passes remain separate classes.

Equipment-04 uses `native-transaction-observer-v4` and
`idempiere-qualified-judge-v5-observer-ms94`. Oracle occasionally supplied an
incomplete counter tuple before supplying a complete tuple for the same session
and transaction while the target write lock was still held. Observer v4 can
replace that incomplete baseline with the complete one. It never imputes zero,
replaces a complete baseline, or accepts an intervening commit. The final witness
still requires one rollback, increased undo, unchanged commits and transaction
end. The frozen source snapshot prevents development edits changing a running
campaign's implementation. See [the observer diagnosis](../../calibration/idempiere-ms94/OBSERVER-v4.md).

## Declared limits

- Lock-duration and duplicate-retry mutants are not scored. A native unique
  business-key index prevents the proposed duplicate retry; prevention is not
  counted as a judge rejection. Duplicate invoice-line cardinality is tested.
- The rollback mutation models a leaked committed draft; it does not disable
  the database's rollback implementation.
- The timestamp mutation is a paired comparison rejection using distinct native
  second offsets. The accepted timestamp exception remains narrowly scoped.
- Operator signatures establish provenance, not independent third-party
  attestation. Human review records preserve the operator's explicit statements.
- No production qualification, unfamiliar-journey performance or autonomous
  generation rate is established by Stage A.
