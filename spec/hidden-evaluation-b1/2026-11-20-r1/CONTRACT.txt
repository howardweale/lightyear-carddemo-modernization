The B2 port has exactly two operations:
1. evaluator.preflight(material: PublicMaterial) -> True. Called once before any durable claim or private read. Validate both B2-owned byte documents and their dependencies. Any failure refuses. It must never start a candidate or access an identity, private vault or decrypted input.
2. evaluator.compare(frames: list[bytes], material: the same PublicMaterial, end: absolute time.monotonic deadline) -> exact bool. Called once, only after the full H3-A stream has authenticated, age and its process group exited, all broker handles closed, physical confirmation returned and the USB mount/device is absent. Each frame is one canonical H2 checked_case, ordered by zero-based sequence. Full frames remain exclusively in trusted verifier memory. Give only the selected jar, current case's four inputs, timestamp and processing date to the approved candidate path. Never persist frame bytes or case-derived clocks in daemon configuration. All cases must be evaluated once, including after the first difference. Return True iff every admitted comparison passes, otherwise False. Infrastructure, malformed observation, identity, cleanup or deadline faults must raise and cannot produce either verdict. There is no retry/reselection/rebuild.

PublicMaterial is frozen and contains only binding, result, closure, jar, the verified Native Image object, native_qualification, runtime_policy and route_qualification. Fields containing bytes are immutable snapshots. All caller-owned evidence containers are copied at entry. The exact native runtime and public qualification details are B2 responsibilities. No access to the age process, USB fd, H3-A broker, mounts, approval or answer directory is passed to B2 via this material.

Replay and failure states:
Before the claim: refused authority, source, profile, evidence, time or preflight returns the fixed stage2-refused failure and no public verdict.
Once claimed: two durable exclusive claims are made in the fixed owner-only home replay parent. One indexes the original paid authority, one the precommitted completion. The P3 directory/file sync and readback precede any private read. A lost or partial claim is spent. A concurrent call, replacement approval or changed stage-2 operation ID cannot reopen either slot. Never restore or reset these directories. All storage uncertainty stops the operation.
Claimed -> authenticated completion and ciphertext -> bounded anonymous pipe -> authenticated end of stream and successful age exit -> USB removal and no-copy confirmation -> one evaluation -> private terminal record -> public verdict.
On interruption, decline, uncertain OS cleanup, incomplete decryption or any verifier fault, publish no PASS/FAIL. Retain the private spent claim, stop and reconcile local resources under Howard's control. Failure code is stage2-refused. No counts, exception text, private observations or case digests become public. Never resume or run a recovery candidate.
The private claim fields are schema, authority_sha256, result_sha256, commitment_sha256 and jar_sha256. The terminal fields are schema, claim_sha256, removal_sha256 and public_receipt_sha256 (digest of the canonical single-property status object). Hash-check both writes. On success the sole public field is status, with PASS or FAIL. No names, counts, timestamps, timings, stage identifiers or receipt links are added to that public object.

Operator-only custody channel:
The dedicated mount must be observable as its own non-root Linux device and mount in this namespace. Howard verifies the dedicated physical device, independent digest and account boundaries. Before the durable claim no identity is opened. On the private terminal the broker announces only a claim and child PID after a new isolated child is listening. Howard supplies an already-open read-only descriptor from the dedicated medium as stdin to the separately invoked sender (intcalc_h3_usb_channel.py send CLAIM PID). Never provide the identity name to the verifier, packet, argv, environment or log. The sender verifies the peer PID/UID and passes exactly one descriptor directly to the custodian child. That child checks the descriptor's mount and device, duplicates it onto stdin and execs the pin-verified age binary by fd. Only the ciphertext descriptor is named in the child command. Standard output is the private anonymous pipe; standard error is discarded. The verifier parent never holds the identity descriptor. Sender exit and removal of any other identity handle are Howard's responsibility. The pinned age build must support -i - with a named ciphertext input; exercise this path using a separately approved public canary on the PC before private use. After age exits successfully, Howard closes the sender, ejects the medium, physically removes it, checks that no copy remains on either machine and that Codex remained stopped, and answers the private terminal challenge. The verifier checks mount/device absence before and after evaluation. A claimed mount that WSL cannot distinguish or a private namespace that cannot demonstrate absence refuses; do not substitute Docker Desktop. No forensic erasure, swap, crash-dump or protection against a Windows administrator is claimed. USB/WSL qualification, physical checks and any private invocation require separate authorization.
