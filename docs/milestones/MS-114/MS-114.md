## What was delivered

- **Rules for coding agents.** `AGENTS.md` sets the rules every agent works under:
  - CI-only execution;
  - no model calls or signing;
  - frozen POSTTRAN paths;
  - reserved authorization screens;
  - small PRs targeting `main`;
  - which large folders not to open.
- **A map of the repository.** It names where each area's code, tests and CI live. The map's paths are checked in CI, so it can't silently go stale.
- **Status rebuilt automatically.** The factory status page (`current-status.json` and `.md`) is rebuilt after each merge to `main`, and CI refuses PRs that edit it by hand. This removes the main source of repeated merge conflicts.
- **Evidence kept in Releases.**
  - New proof archives and full mutation reports go to GitHub Release assets, with a small manifest committed in their place.
  - A CI check blocks new tracked files over 5 MB, and new ZIP or mutation-report files.
  - Existing dated evidence is unchanged.
- **More reliable CI evidence.** Test collection is guarded, CI reruns are read correctly, and artifact downloads use the right media type.

## Why it mattered

Between 17 and 19 October, several PRs were merged into other PR branches rather than into `main`, so finished work did not reach `main`. PR #403 recovered the stranded account-update Java. The rules above require every PR to target `main`, and limit how many PRs are open at once.
