## 1. Terminal runtime origin and zero-model delivery

The external JDI collector records throwable object identities and the actual
JUnit `ExecutionListenerAdapter.executionFinished` event. The descriptor must
belong to the candidate test; the result must name the same throwable observed
on that thread before completion. Replay authenticates the collector, full entry,
real-clock evidence, bound class bytes and framework call stack. Candidate-written
logs and XML cannot establish terminal origin. Missing framework fields, class
identities or terminal events fail closed; they are never guessed.

Candidate-origin runtime exceptions produce the same closed field shape as B05:
`id`, `category=candidate-runtime-exception`, allowlisted exception class,
`thrown_by=candidate`, source-bound method/line and one/both engine scope. Exception
messages, SQL, document keys and private values are excluded. Support, outside,
application-origin, ambiguous and observed JDBC/VM faults send nothing and remain
equipment-suspect. A caught candidate exception is not a terminal failure merely
because it was observed. Legacy categories retain analyst selection; the frozen
direct categories bypass it.

`tools.ms94_b06_runtime_delivery` writes a signed projection and zero-model inbox,
reads the actual inbox bytes, signs a delivery receipt, and independently replays
the projection, route, signatures and consumed bytes. This is expressly a
**zero-model preflight consumer**, not a model invocation or evidence that a
measurement builder was called. The native receipt binds the resulting delivery
and uses its independently replayed suspicion disposition.

[J1 preflight acceptance](runtime-preflight-acceptance.json) explicitly requires
a retained complete pair and a planted candidate-origin exception delivered
directly, plus empty-delivery support/outside controls. Its native acceptance
has not run. Compilation in the pinned image, the JUnit/framework class catalog
and actual terminal-event controls remain required in the approved Docker group.

Validation for this increment: 73 offline B06 tests passed and a host JDK 21
syntax compilation passed. Zero Docker runs, native pairs, JVM attachments or
model calls. Synthetic stream and signed-fixture tests provide no native credit.
Exit code 124 remains a candidate failure even if the candidate explicitly chose
that code; it cannot become a pass.
