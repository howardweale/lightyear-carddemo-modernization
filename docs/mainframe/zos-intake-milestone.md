# CardDemo z/OS folder intake milestone

Date: 2026-10-02 (America/Los_Angeles). Implementation: `41886611e202c35667514a751af27469a4b90df7`,
based on main `e24d77822f7097dea3b1207026a55a95d8e6060f`.
This is delivery-intake readiness for Maintec's October 5 files, not a native z/OS
qualification or a new MS94 measurement. Operator review; not independent attestation.

## Operator outcome

Each stage now has a command: freeze and sign the delivery, report gaps, decode
records and job logs, compare repeated runs, measure before/after changes, bridge
INTCALC inputs to the unchanged Java candidate, sign its verdict and replay offline.
The [Monday runbook](monday-runbook.md) gives the exact command sequence and the
metadata Maintec must supply.

Bindings come from public CardDemo commit `59cc6c2fd7ebd7ef7925cad552a01a4b8b6e4d5e`.
They cover INTCALC, POSTTRAN, CREASTMT and TRANREPT, including the daily record and
validation trailer in POSTTRAN rejects. The implementation extends the existing
strict decoder, preserves EBCDIC bytes and text padding, and refuses ambiguous
layouts or unsupported blocked/spanned framing with a resend instruction.

The original delivery and every derived record value stay under ignored arrivals.
Intake decisions and normalization proposals use the existing Control Tower flow
with hashes and counts. Timestamp proposals require explicit signed approval;
other differences, added/deleted records or missing evidence prevent proposal.
No rule is silently applied and no historical verdict is rewritten.

## Evidence and validation

Local validation passed 45 new intake tests, 63 existing mainframe tests, 18
decision-service tests, 11 Decision Console tests and 11 Java tests. One optional
agent-SDK Console test was skipped locally. All seven required broken-delivery
cases were detected, alongside evidence-tamper and approval-refusal regressions.

The final public synthetic rehearsal had three runs, 50 files, zero intake gaps,
one unapplied timestamp proposal and an equivalent signed Java verdict reproduced
offline without another candidate execution. The signed report content hash is
`3ff536a5a8283c32da1eca322596c73b0e27c03d6de6a3b8b15e75e1071baf49`;
the verdict hash is
`2528b8b239d9bca24f85201ec4e905fb99d5a2b5e20fac1d68d8114049c24272`.
The [readiness record](zos-intake-readiness.md) retains the full local validation
scope and hashes. Repository CI adds Windows and Linux public-only rehearsals;
the PR checks are the authoritative record of their results.

The first PR run passed both intake rehearsals and 22 of 23 checks. Windows
completed all 2,167 unit tests in 1,627 seconds, then the 30-minute CI job limit
interrupted the follow-on estate checks. The Windows CI allowance was increased
to 45 minutes with every test and verification stage retained. This changes only
the CI job allowance; no measurement/controller budget or frozen input changes.

The pinned public ASCII/EBCDIC pairs contain documented line-ending, filler and
two substantive source-pair discrepancies. The [bridge exception record](bridge-fixture-exceptions.md)
explains them. The bridge retains the EBCDIC values; these exceptions never change
Maintec data or the Java-versus-z/OS comparison.

## Publication and remaining boundary

Publication comprises implementation, public-source bindings and fixtures, tests,
CI and documentation. The actual rehearsal arrival, execution logs, decoded records,
candidate artifacts and signing keys remain local and ignored. The task used its
own clone and virtual environment, with no Docker or model calls and no changes to
B05, `work/ms94` or execution snapshots.

The synthetic after-images were generated by the local Python reference. Real
Maintec evidence is still required to measure native equivalence. Complete transfer
metadata, binary before/after images, readable job output and actual date parameters
remain prerequisites. POSTTRAN, CREASTMT and TRANREPT have observation support only;
they do not gain a Java candidate in this milestone.
