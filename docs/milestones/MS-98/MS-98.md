# MS 98 Native T SQL procedure verification

Reconciled October 14 2026.

This milestone makes database procedure verification executable on SQL Server and PostgreSQL. A customer can inspect observed differences, coverage gaps and policy-dependent behavior instead of relying only on translated SQL looking similar. The qualification described here uses an authored public corpus on an approved Linux VM; it is not a blanket customer migration certificate.

## Delivered capability

A ScriptDom inventory, typed invocation contracts, fresh database resets and native adapters capture table effects, results, errors and procedural coverage. Exact mappings retain ordering, datatype, collation, compatibility and session requirements. Unsupported dynamic behavior and missing evidence are refused. Signed captures can be replayed offline on Linux and Windows without another database execution.

Review corrections cover result ordering and ties, typed arguments, sequence effects, dependency inventories, error mappings, generated inputs and bounded shrinking. Each revision retains its own evidence. Earlier failures are not changed into successes when a later implementation passes.

## Measured evidence

The latest revision 9 record reports 86 of 86 expected procedure-and-variant outcomes across 108 native pairs. Nine coverage controls, eight ordering controls and an 18-pair generated-input and shrinking integration were verified. All archives independently replayed. The dedicated VM was stopped after 3,767.859 seconds, within the authorized window. No model calls were used.

These are expected-outcome results: detecting the deliberately wrong variants is a success of verification, not an assertion that every pair is equivalent. Earlier records contain different counts and an unsuccessfully finalized run; they remain dated historical results and must not be pooled with revision 9.

## Remaining work

Customer dependency closure, customer-owned policies and certificate release remain separate. The public qualification does not prove security, concurrency, performance or complete application equivalence. The exact source, mapping, collector and evidence versions remain part of every claim.
