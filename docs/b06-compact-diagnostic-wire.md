# Compact diagnostic wire (host validation)

The `d3` diagnostic envelope keeps `kind`, `sequence` and `checkpoint` visible. Its base64 payload is a zlib stream using the fixed 32 KiB dictionary generated by the Java and Python code. The decoded body contains every remaining logical event field, including timestamps, locations, policy, audit indexes, lifecycle actions and full JDI detail. The dictionary contains only public JDK method templates with synthetic zero identifiers, hashes and clocks. It never depends on earlier observations, private captures or target values. A fresh reader can decode any individual record.

`dispatch-refused` records remain plain for inspection. Existing plain records and `deflate-json-v1` detail records remain supported. Expanded bodies are bounded to 256 KiB; malformed envelopes, framing collisions, duplicate keys, non-JSON numbers, bad dictionaries, trailing compressed data and oversized inflation are refused. The original wire event remains authoritative for signatures, stream hashes and byte quotas. The writer serializes the logical body once and the final envelope once; it does not serialize the final record again to count it.

Read-only conversion of the complete, hash-verified r4 host output covered 347,256 records and all 273,061 diagnostics. Every logical field round-tripped and the structural Audit terminal state was unchanged except its byte total. Diagnostic wire size fell from 134,217,565 to 52,562,139 bytes (39.16% of the original; 2.55 times smaller). Counts and hash bindings are in [the aggregate report](b06-compact-diagnostic-wire.json). The 500,000-record and 128 MiB caps are unchanged. This comparison rewrote no source evidence and does not establish completion of a new workload or native success.

Focused tests cover Python corruption cases, metadata evolution without lost fields, sealed-wire analysis consumers, real Java dictionary agreement and emission-byte accounting, and short real-JDI strict/diagnostic paths. Historical r1/r3 prefixes retain their expected incomplete termination under the new reader. The full host workload must still run with the combined memory changes before acceptance. The engineering hold remains in force; no Docker, native run, model call, qualification or measurement credit is authorized by this codec.
