Fresh held-out input generator (no PR yet, r3)
Exact input-generator proposal only. No expected answers, oracle execution,
freeze, case generation by an agent, image publication, dispatch or seed handling
is authorized. No generated output is in this proposal or its Release.
Howard alone supplies a 256-bit seed via hidden prompt; not argv/env/file/log.
The code never invents or logs a seed. Python cannot promise memory erasure;
operator custody and an isolated attended process remain prerequisites.
HMAC-SHA256 domain-labelled rejection draws reproduce the same input set from
the same seed/profile/count. Count1..64 is a hard bound, not an approved run size.
The first profile samples public source branches: empty balance file, transitions
across1..8accounts and1..4categories, scaled signed balances, disclosure rates,
direct/default/missing disclosure, missing account and missing cross-reference.
Signed DISPLAY values encode preferred C/D (positive zero C). Every complete
input is checked by merged preferred_signs and bridge, including actual key-order
equivalence on ACCTFILE and TCATBALF. No zone-F exemption. Copybooks, source,
validator, record parser and generator are hash-bound before the prompt.
No retired cases, hidden results, public expected outputs or per-program oracle
are generator inputs. Public source/copybooks define fields and lookup branches;
this coverage proposal is not claimed exhaustive, mainframe-proven or independent
of its author. Claude reviews source and families, never runtime generated output.
Files are created exclusively under a fresh directory in Howard's resolved0700
private parent, inputs.json mode0600, readback before commitment. Non-POSIX refuses.
Only SHA256 of the private input payload is printed; no case ids, per-case hashes,
seed, paths or generated bytes. Disk/write failures preserve state and refuse;
no automatic retry or cleanup. The private input commitment is NOT an answer-key
commitment, qualified reference receipt or admission token.
Expected-answer generation remains a separate approved qualified-reference stage:
run unmodified COBOL under the adopted per-run pinned-build profile, encrypt answers before their first
persistent write to a Howard-approved recipient, publish commitments only. This
packet deliberately provides no permissive placeholder for that missing stage.
No static private seed, generated case or readable expected answer may enter CI,
Release, graph view, model context or logs. CI uses visibly public synthetic seeds
solely for tests and uploads no generated files. No generator run in this task.
Before any real generation Howard must approve exact source tree/manifest hash,
count, private destination and operation; a real seed never goes to an agent.

G1-G4 distribution: uniform labelled integer draws partition scenarios 70% normal,
15% mixed direct/DEFAULT fallback (at least two accounts), 5% missing rate,
5% missing account, 5% missing xref. Failure target is the last account; earlier
accounts retain their ordinary direct rates. Normal scenarios alone sample empty
balances with probability1/8: 8.75% of all cases are EOF-only, 61.25% normal
nonempty; fallback and abend scenarios remain nonempty. These are expected draw
frequencies, not guaranteed outcomes/coverage in any finite private suite.
Per case, independently, probability1/16 selects extreme magnitudes: balances
absolute900000000.00..999999999.99 and nonzero rates9000.00..9999.99 percent.
Otherwise balances are uniform within +/-10000000.00 and nonzero rates0.01..36.00
percent. For each distinct disclosure category/rate draw, probability1/8 yields
zero rate, in either magnitude regime. Current balances share the case regime.
Thus zero-rate skipping, positive/negative interest, transitions, EOF, direct and
fallback lookups, three abends and rare high-order truncation paths are sampled.
Overflow/receiver wrap is not guaranteed: zero rate, early abend and values canceling
can prevent it; code review and later private qualification determine coverage.
Clock spelling remains YYYY-MM-DD-HH.MM.SS.ffffff with zero sub-hundredths.
Fixed Refused codes are printed only from the closed REFUSAL_CODES set; unknown
faults become fresh-inputs-refused. No dynamic exception message is printed.
The changed generator source hash is re-pinned. No seed or case was generated in
preparing this packet. Synthetic tests are authored for CI only.
