# MS #48 - iDempiere Oracle Reference Estate Inventory

> **Status:** Complete
>
> **Release:** 0.48.0
>
> **Date:** 2026-09-01
>
> **Audience:** Customers, partners, executives, architects, delivery teams, and assurance reviewers

## Executive summary

MS #48 - iDempiere Oracle Reference Estate Inventory converts a specific part of the LIGHTYEAR modernization approach into a governed, reviewable capability. Replaces a toy Oracle source with a pinned, enterprise-shaped ERP reference estate while measuring its size and preserving the boundary between static inventory and behavioral proof.

## Why this matters to a customer

Replaces a toy Oracle source with a pinned, enterprise-shaped ERP reference estate while measuring its size and preserving the boundary between static inventory and behavioral proof.

The practical result is a narrower, evidence-backed decision instead of a broad modernization claim. The milestone packages capability, proof, and limitations together so commercial, architecture, delivery, security, and assurance teams can review the same record.

## What the milestone delivers

- A supported iDempiere release-13 pin at commit 731515dcdd5278b843db33b9d3109d155b881951 with source, tree, date, and GPL-2.0 license identity.
- A reproducible inventory tool that refuses a dirty checkout or any commit other than the pin and emits only derived counts and source-path references.
- A measured 12,565-file estate with a 4,520-node, 36,819-edge internal Java source-unit graph and 2,823 Oracle SQL files.
- An order-to-cash slice with 12 seed source units and a one-hop graph of 181 nodes and 497 edges.
- A procure-to-pay slice with 12 seed source units and a one-hop graph of 177 nodes and 475 edges.
- Curated document-flow maps that preserve the shared physical tables and the IsSOTrx and IsReceipt business selectors.
- Eight prioritized Oracle semantic fixtures covering empty-string/null, NUMBER precision and scale, DATE arithmetic, NVL/DECODE coercion, ROWNUM ordering, SELECT FOR UPDATE, NO_DATA_FOUND, and LOB boundaries.
- Regression checks for pin identity, graph measurements, slice semantics, corpus posture, non-vendoring, and explicit claim boundaries.

## How it differs from earlier work

MS #43 qualified a bounded Oracle source adapter and MS #47 made evidence graph identity operational. MS #48 selects and measures the larger Oracle-equivalent reference estate that will supply future source and graph coverage without importing it into product runtime or upgrading static evidence into equivalence.

Earlier work remains useful evidence, but it is not automatically promoted into this milestone. A successful parser, simulator, local comparison, or generated artifact is not presented as live platform equivalence or production readiness.

## What a customer can do with it

A customer can use idempiere oracle reference estate inventory as a bounded decision and delivery capability. It can be attached to the customer's approved source package, owners, policies, target architecture, acceptance criteria, and authorized evidence.

Unresolved semantic loss, policy decisions, unsupported behavior, and live-evidence requirements remain visible rather than being averaged into one pass/fail statement.

## Evidence and acceptance posture

The milestone is complete as a repository capability because its committed implementation and release record are present. Customer qualification remains claim-specific: only the delivered behaviors listed above are supported, and only at the evidence class recorded by their underlying receipts and gates.

A customer review should confirm:

1. the exact source, graph, policy, fixture, and artifact identities referenced by the evidence;
2. the difference between deterministic development evidence and authorized live evidence;
3. every policy decision, lossy transformation, unsupported behavior, and explicit exclusion;
4. the acceptance gates that passed and the live or production gates that remain blocked; and
5. that later changes have not invalidated the content-addressed evidence.

## Boundaries and claims not made

- The iDempiere source is not vendored, built, executed, translated, or attached to product runtime.
- The measured graph is a static Java source-unit dependency graph, not a complete application-dictionary, runtime, transaction, or database-foreign-key graph.
- The two mapped slices are upstream reference flows, not customer source or observed customer transactions.
- Oracle's official sample schemas are identified as the dialect authority but are not acquired or executed in this milestone.
- CloudBank remains the intended modern destination, but no iDempiere-to-CloudBank mapping is claimed.
- Native Oracle behavior, application equivalence, migration completion, and production readiness remain false.

These boundaries are part of the deliverable. They prevent bounded development evidence from becoming an unsupported customer promise.
