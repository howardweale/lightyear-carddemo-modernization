L1a · Staged public graph-off run admission

GraphOffAdmission implements S1's admit(canonical_binding_bytes, phase_deadline) port. Its inputs are public evidence and human authority. It cannot start the key owner, contact a model, build a candidate or operate the private host. The only remote operation in its default reader is an anonymous read of the named public H2 commitment. CI substitutes synthetic evidence.

Preparation order
1. Howard runs H1 and H2 under separate approvals. Only H2's two-field public commitment is published by the operator as COMMITMENT.json. Record repository, release ID, asset ID and tag. Admission uses the API's public release identity and asset digest. Its effective publication time is the latest of release publication, asset creation and asset update. An unavailable or modified publication refuses admission.
2. L1c stages the reviewed P2 binding and archive and obtains fresh evidence from the appropriate owner. For each of main_green, mac_tls_1, ledger_volume, disk_headroom, public_worker, and measured_bounds_and_deadlines, a review envelope names its kind, source commit/tree, subject, observed_at, valid_until, pass decision and underlying receipt hash. Return the actual attachment. The human reviews these claims, limits and expiry when binding the intent. L1a verifies those exact bytes and joins. It does not independently repeat a qualification or authenticate a self-issued claim. Detailed bounds/deadline and TLS experiments are V1 work.
3. A clean reviewed checkout supplies its commit, tree and fixed path-to-module SHA256 map. implementation_sha256 is the controller canonical digest of that map. runtime_profile_sha256 is the digest of the build_profile dictionary. The worker source, helper, frozen manifest, reviewed suite and P5 image IDs have independent joins. The P2 loader still checks the unpacked case data at use.
4. S1 binding_intent_sha256 covers every binding field except authority_sha256. Include the exact graph-off costs in the intent: 37,664,000 microdollars maximum reservation, ceiling 37,670,000, 17,520 seconds, five repairs, fixed model and Flex tier. Count and generation input rates are 22 quarter-microdollars per token; generation output is 99. Howard explicitly accepts the count-billing assumption. The authority binds the exact intent bytes and issuance timestamp; its raw file hash fills authority_sha256. This construction avoids a circular hash.
5. L1b receives the approval hash from Howard independently of the staged files. It supplies the fixed owner-only replay directory previously reviewed on the Mac. The same directory must be used across launches even when individual run output locations change. Approval files, source checkout and imported modules must remain under trusted operator control. The default publication reader requires network access only before candidate execution. An injected reader is a trusted integration boundary; untrusted config cannot choose it.
6. The narrower start window and every evidence expiry must be current. P3 exclusively creates the durable operation-ID directory and stores the hash-checked admission receipt. The launcher enforces the original wall and monotonic deadlines and makes the key prompt reachable only after a successful admission. A lost receipt or uncertain claim consumes that operation; no resume. P3 distinguishes operating-system durability from demonstrated power-loss survival. L1a's port does not grant any real run authority on its own.

The separate private verifier alone evaluates the previously selected jar. Source and receipts for public staged work cannot authorize private steps. The architecture entry belongs to the final docs-only proposal.
