## What was delivered

Six CardDemo screens now run as a web application: a TypeScript browser front end over Java services and typed PostgreSQL tables. The six screens are sign-on, menu, account view, account update, and the pending authorization list and detail.

The verifier replays every session against an independent reference that executes the pinned COBOL. It then compares each returned screen and the full PostgreSQL state after each interaction.

## Proof

- CI run 39127778944 passed all 120 journeys and all 678 interactions, both through the API and in a real browser. Each comparison covered the returned COMMAREA and every database table.
- Strict mutation testing killed 701 of 768 mutants (91.3%). The 49 survivors, 17 uncovered mutants and one timeout are disclosed and get no credit.
- The unsigned 18 October receipt and the seven original CI archives are retained with verified hashes. An unsigned Factory review request binds the evidence commit.
- PR #367 made the access adapters read the migrated typed tables rather than shadow raw tables. It also returns real CICS response names and adds the DL/I `GN` call. The forty-case IMS replay now compares returned bytes and the database state after each call.

## What this does not establish

- The comparison ran on a mainframe twin with public data and labelled synthetic IMS rows. No native CICS, IMS or z/OS equivalence is claimed.
- At this milestone the screen logic still ran through a statement engine compiled from the COBOL. Replacing it with hand-written Java is recorded in MS 111.
- The reference and the candidate share the BMS map parser and the data-layout codec. An independent layout check is in progress and not yet merged.
- These screens were built in developer sessions with AI agents, not by an end-to-end dark-factory run. The factory-built screens are a separate, later milestone.
